## Invariants

- Pure deterministic traces: algorithms copy input arrays and use fixed pivot,
  traversal, and tie-breaking order.
- Stable indices: sort/search steps refer to array positions; traversal steps
  refer to `graph.nodes` positions.
- Accurate counters: `comparisons` increments with each `compare` step and
  `swaps` increments with each `swap` step.
- Visualizer contract: React consumes a supplied trace and replays steps; it
  never calls trace generators.

## Anieyrudh Filter pass

Date: 2026-05-16
Filter version: aniegpt v1.0

### P0 issues

- Potential P0: pretty animation could disagree with real algorithm operations.
  Resolution: traces are generated by the reference implementation and tests
  assert final arrays plus counter/step agreement.
- Potential P0: input arrays could be mutated during tracing.
  Resolution: every trace generator copies inputs before work; tests freeze and
  compare input arrays.
- Potential P0: binary search over unsorted input would teach a false trace.
  Resolution: sorted ascending input is validated before binary search traces.

### P1 issues

- Merge/insertion traces use `set` operations rather than artificial swaps.
  Resolution: counters keep `swaps` at the real swap-step count and expose moves
  explicitly as `set`.

### High-bandwidth questions surfaced

- Should future graph traversal traces support undirected expansion as an option,
  or should callers materialize both directed edges explicitly?
