Paideia collaborator brief

Help build the learning infrastructure we wish existed.

Paideia, including the Concepts For Everyone public effort, turns hard ideas into clear explanations, concept maps, interactive simulations, and reusable learning tools.

Our mission: make deep learning easier to build, easier to improve, and easier for every learner to use.

Paideia Curriculum Field Engineers

The role

We need people who stand close to the learner.

A Curriculum Field Engineer, or CFE, is the bridge between real learners and the Paideia platform. You do not need to start as a professional engineer. You need sharp eyes, care for learners, and the will to improve what exists.

You can contribute without writing code.

A useful CFE contribution can be a classroom observation, a clearer explanation, a misconception report, a tested worksheet path, source notes, review feedback, or a request for a better simulation.

01

Stress-test the work

Try lessons, maps, and simulations with real people. Find what confuses them and what finally clicks.

02

Shape it for context

Adapt containers for a class, syllabus, school, cohort, or learner group without breaking the shared structure.

03

Find the gaps

Spot missing explanations, weak examples, absent concept maps, or simulations that do not yet exist.

04

Feed the core

When a local need repeats, turn it into a request for a reusable tool that everyone can use.

The core team cannot see every classroom. CFEs make Paideia real in the field.

Words we use

The system has a few names. The idea is simple.

These terms keep the project organized so humans and agents can work on one useful piece at a time.

Container

One complete concept package: explanation, concept map, problem-solving path, media, embed API, and any declared simulation.

Core

Reusable tools shared across many concepts, such as math kernels, graph layout, simulation runtime, and UI controls.

Kernel

The tested math or logic a simulation relies on. Kernels keep calculations consistent across containers.

Agent-friendly

Structured enough that AI tools can help build, test, and review without replacing human judgment.

Why it matters

Good learning tools are not made in a vacuum.

A simulation can be beautiful and still miss the misconception. A concept map can be correct and still fail a student. The field is where truth shows up.

Your feedback can become a shared platform upgrade.
  • A better vector tool can help every physics container.
  • A clearer problem-solving path can help every learner stuck on the same pattern.
  • A missing concept map can reveal a gap across a whole syllabus.
  • A request from one classroom can become infrastructure for thousands.

Local pain should become shared capability.

That is the core idea. A CFE turns real friction into better containers, better maps, better simulations, and better reusable tools.

How the work flows

Simple loop. Serious impact.

The loop is practical: observe a learner, adapt a small part of the system, test it, report evidence, and improve the shared platform.

ObserveWhat is hard for learners?
AdaptMake the container fit the context.
TestUse it with real people.
ReportShow what worked and failed.
ImproveTurn the lesson into shared tools.

AI can help with the coding. Humans must protect the learning.

Paideia is built to be agent-friendly for development and human-friendly for learners. CFEs help keep both promises true.

Start here

Pick the entry point that matches what you can see.

You can contribute without writing code. Start with one observed learning friction, one concept, and evidence from a real learner or source.

I have no code experience

Write down what a learner misunderstood, what helped, and what still failed.

Use the agent workflow guide to turn that observation into a narrow task.

I found a learning problem

Open an issue or field note with the concept, learner context, evidence, and what outcome would count as success.

Start from the issue templates, then attach citations or mark uncertain claims as needing verification.

I want an agent to help me

Give the agent one target and tell it to read the repo contracts before writing.

Start with prompts from Agent Workflows.

I want to build a container

Use the v2 container shape: explanation, concept map, simulation, problem-solving path, media, embed API, sources, and audit notes.

Read the container specification before changing files.

Agent-ready issue format

Include the concept, learner group, observed friction, attempted explanation or simulation, evidence, proposed container or core request, and safety/provenance notes. Anonymous observations are enough; do not include private learner data.

What you can build

Pick the gap you can see clearly.

A single useful improvement is better than a broad plan no learner has touched.

Containers

Complete concept packages with explanations, simulations, maps, media, and problem-solving paths.

Concept maps

Prerequisites, downstream ideas, sibling ideas, and misconception graphs that help learners orient themselves.

Simulations

Interactive tools that let learners change something and see why the result changes.

Core requests

Better shared components, kernels, validators, and authoring tools when many containers need the same thing.

The rule of thumb

If it is specific to one lesson, improve the container. If many lessons need it, ask for a core feature. Reusable math and rendering logic belongs in core/, not inside one container.

Safety and reuse

Protect the project while you help it grow.

Public contributors can move fast only if source, licensing, and reuse boundaries are clear.

Plain-language safety box

  • Cite sources. If a claim is not verified, mark it as needing verification.
  • Do not include student names, grades, private messages, school records, or identifiable classroom data.
  • Get permission before sharing classroom artifacts, and anonymize learner feedback before it enters an issue or PR.
  • Do not paste proprietary textbook chapters, paid course material, or copyrighted worksheets into the repo.
  • Do not copy GPL, AGPL, LGPL, proprietary, or unclear-license simulation code into Paideia.
  • Paideia code is MIT. Curriculum content is CC-BY-4.0.
  • When a non-friendly dependency has behavior we need, use the clean-room process.
  • AI may help draft, test, or refactor, but humans own accuracy, provenance, learner safety, and educational judgment.

The Filter is a critic, not an author.

The Anieyrudh Filter helps block weak claims and unsafe educational work. It does not replace sources, classroom evidence, or human review.
