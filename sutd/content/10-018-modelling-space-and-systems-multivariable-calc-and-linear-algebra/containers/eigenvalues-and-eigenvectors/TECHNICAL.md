### P0 issues

- None observed. Container shape validates. Prediction gate is declared and asserted in the Playwright test. The reveal renders an SVG eigenspace plot with one line per real eigenvalue (blue for the larger eigenvalue, green for the smaller) and a clear complex-case readout when the discriminant is negative. Computation goes through `core/linear-algebra` (`matrix2`, `determinant2`, `trace2`); the eigenpair solver inside the sim is a tiny 2x2 quadratic and is intentionally local because it is the explicit pedagogical surface of this container — `core/linear-algebra.eigenvectors2` returns an opaque eigenpair which would defeat the goal of teaching the procedure. The complex-case explicit `(real, imaginary)` reporting fills the gap that the kernel's real-only eigenvector contract leaves open.

### P1 issues

- Formula colours pair `lambda` (blue), `T` (green), `D` (orange), and discriminant `Delta` (purple); the legend uses the existing `.legend-swatch` classes. Manipulation visibly merges or splits the eigenspace lines as the discriminant crosses zero. Substitution and per-case interpretation are present.

### P2 issues (deferred)

- Add a small inline plot of the characteristic polynomial `y = lambda^2 - T lambda + D` with the eigenvalues marked on the lambda-axis to make the "roots of a quadratic" framing visible.
- Add a slider for an arbitrary candidate direction with a real-time "is this an eigenvector?" verdict to bridge to the existing `sutd.freshmore.eigenvector-transformations` container.
- Add a transfer problem on Markov chain steady states as a real-world eigenvalue-1 example.

### High-bandwidth questions surfaced

- Should `core/linear-algebra` grow a public `realEigenpairs2` helper that returns the discriminant verdict and explicit complex-case coefficients so containers like this one no longer need a local solver? Worth a `core-change-proposal` issue if more containers ask for the same surface.
